## Findings

Severity reflects impact on this project: the dashboard can start billable work on two AKS clusters.

### Fixed

| # | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| 1 | High | **Cross-site request forgery on live-cycle control.** Any web page open in the operator's browser could `POST /api/cycle/run` and start a real cycle. | A POST with `Origin: https://evil.example` returned 202 and called the runner. | POSTs must be same-origin (`Origin`, `Sec-Fetch-Site`). `tests/test_web_server.py` |
| 2 | High | **DNS rebinding.** The server answered requests for any `Host`, so a hostile page could read the API and, with (1), drive it. | `GET /api/cycle` with `Host: evil.example` returned 200. | Requests must name a known host; `--allowed-host` adds names. |
| 3 | Medium | **No restriction on remote clients** when started with `--host 0.0.0.0`: anyone on the network could start cycles. | Code reading; no check on the client address. | Control endpoints accept only loopback clients unless `--allow-remote-control` is given. |
| 4 | Medium | **Unescaped receipt fields in the page.** Values from receipts, including the region string the LLM proposed, were written to `innerHTML`. | A receipt carrying `<img src=x onerror=…>` reached six elements unescaped (Node harness with a stub DOM). | All server-reported values are escaped; a Content-Security-Policy with `script-src 'self'` backs this up. |
| 5 | Medium | **Thirteen dependencies with published advisories**, among them urllib3 2.3.0 (used for every outbound request) and pillow. | `pip-audit` on the exported lock. | Twelve upgraded. urllib3 needed the Kubernetes client 37.x, which lifts the `< 2.4` pin of 34.x. |
| 6 | Medium | **Auto-stop safety net could fail silently.** An unreadable deadline file meant the clusters were never stopped; `1.5` hours was rejected; a missing `.env` key or a failed `az aks stop` went unreported. | Reproduced with a stub `az`. | Last valid deadline stays in force; retries; non-zero exit and a clear message if a cluster is left running. |
| 7 | Low | **Source files and directory listings served.** `/server.py`, `/live_cycle.py` and `/js/` returned 200. | Reproduced. | Only page assets are served. |
| 8 | Low | **No browser security headers** (framing, MIME sniffing, CSP). | Response headers. | Added; verified in a browser that the page, fonts and all panels still work. |
| 9 | Low | **Infinite carbon intensity accepted.** Python's JSON decoder reads `Infinity`; `CarbonPoint` allowed it through to the optimiser. | `CarbonPoint(…=inf)` validated. | Non-finite values rejected in `CarbonPoint` and in the proposal's expected latency. |
| 10 | Low | **A half-written receipt broke the status endpoint.** `summarize_run` raised on a partial last line of `cycles.jsonl`. | Test with a truncated file. | Such runs are skipped until complete. |
| 11 | Low | **Readiness check and Job cleanup could target different clusters.** The check used the configured contexts and namespace; the live-cycle runner used hard-coded ones. | Code reading. | The runner receives the same settings. |
| 12 | Low | **Importing `web/server.py` read `.env` into the process environment**, and quoted values kept their quotes. | Code reading. | Settings are read once in `main()`. |
| 13 | Low | **Release workflow used floating action tags and kept the checkout token**; the image installed an unpinned uv. | Workflow and Dockerfile. | Pinned to the SHAs CI already uses; uv pinned to 0.13.7. |

- `pytest`: 143 passed (92 before; 51 added).

- `pip-audit` on the exported lock: one advisory (item A).
- Kubernetes client 37.0.1 with urllib3 2.8.0: `tests/test_executor_kube_client.py` runs the executor through the real client against a stub API server over HTTP (kubeconfig loading, Job create and read, pod list, log read).
- Controller image built from the new Dockerfile: imports every optional integration, reports version 1.0.0, `carbon-scheduler --help` runs, uid 10001, `/app` writable, no `uv` binary.
- Dashboard opened in a browser against the real Electricity Maps feed: no console errors under the new policy; live banner, cluster badges, history table, recorded results, topology walkthrough and same-origin reset all work; a cross-origin request from the page is blocked.

- **A live cycle on AKS.** Both clusters were unreachable (stopped), and a run costs money. The Kubernetes client upgrade is therefore verified only against the stub server. Run one cycle before relying on it: `uv run carbon-scheduler --config config/experiment.yaml --mode milp_only --target-config config/targets.yaml --max-cycles 1`.
- **The GitHub workflows.** The edits to `ci.yml` and `publish-container.yml` have not run on GitHub.
- **PowerShell and Bicep provisioning.** Not executed.

## Behaviour changes

- `web/server.py` refuses requests for host names it was not started for, cross-origin POSTs, and control requests from other machines. See "Launch Operator Dashboard" in the README for `--allowed-host` and `--allow-remote-control`.
- `http://<host>/server.py` and similar paths now return 404.
- `scripts/aks-auto-stop.sh` exits with status 2 on bad arguments or missing configuration, and 1 if a cluster could not be stopped.
- The `kubernetes` extra accepts client versions up to 37.x; `dev` requires pytest 9.
- A provider response with a non-finite intensity is treated as having no usable point, which leads to the cache fallback or a hold.
