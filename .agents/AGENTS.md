# Workspace Behavioral Constraints & Engineering Standards

## Mandatory Engineering Standards (Rigorous Implementation)
All agents operating in this workspace must strictly follow these rules:

1. **No Partial Implementations or Laziness**:
   - Never leave TODOs, placeholders, ellipses (`...`), or incomplete code blocks unless explicitly authorized by the user.
   - Deliver full, end-to-end, production-ready implementations even if it takes more time and effort.
2. **Think Fully Critically**:
   - Analyze requirements, architectural implications, edge cases, and failure modes before writing code.
3. **Follow Best Practices**:
   - Write clean, maintainable, secure, and idiomatic code adhering to established industry and codebase conventions.
4. **Do Not Hallucinate**:
   - Verify all library APIs, methods, and syntax. Never invent non-existent functions or configuration keys.
5. **Search the Internet When Needed**:
   - Proactively search the internet or official documentation whenever uncertain about an API, modern usage, or bug resolution.
6. **Ask Questions & Do Not Assume**:
   - If requirements are ambiguous or critical context is missing, ask the user for clarification instead of making assumptions.
